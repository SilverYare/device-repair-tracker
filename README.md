## Назначение

Приложение предназначено для учёта устройств, принятых в ремонт, и отслеживания
статуса их ремонта. Сервис позволяет клиенту оставить заявку на ремонт, мастеру —
взять её в работу и обновлять статус, а администратору — контролировать загрузку
мастеров и сроки выполнения работ.

## Целевая аудитория

- Владельцы сервисных центров по ремонту бытовой и компьютерной техники.
- Мастера по ремонту.
- Клиенты, сдающие устройства в ремонт.

## Предметная область

Предметная область — оказание услуг по ремонту устройств. Жизненный цикл заявки
включает этапы: приём устройства, диагностика, согласование стоимости, ремонт,
выдача устройства. Для каждой заявки фиксируются устройство, клиент, ответственный
мастер, текущий статус и стоимость работ.

## Основные сущности и классы

Начиная с ПР3 предметная область представлена объектной моделью: сущности
реализованы в виде классов, связанных друг с другом.

### Класс `Person` (базовый, абстрактный)

Общий предок `Client` и `Master`.

**Атрибуты:**
- `id` — идентификатор;
- `name` — ФИО;
- `phone` — телефон.

**Методы:**
- `role()` — роль в системе (переопределяется в подклассах);
- `__str__()` — строковое представление.

### Класс `Client(Person)`

Клиент — владелец устройства.

**Дополнительные атрибуты:**
- `email` — адрес электронной почты.

**Методы:**
- `role()` → `"клиент"`;
- `from_data(data)` — создать клиента из словаря (`@classmethod`);
- `to_data()` — преобразовать в словарь;
- `__str__()`.

### Класс `Master(Person)`

Мастер, выполняющий ремонт.

**Дополнительные атрибуты:**
- `specialization` — специализация.

**Методы:**
- `role()` → `"мастер"`;
- `from_data(data)` (`@classmethod`);
- `to_data()`;
- `__str__()`.

### Класс `Device` (базовый, абстрактный)

Базовый класс устройства.

**Атрибуты:**
- `id` — идентификатор;
- `model` — модель;
- `serial_number` — серийный номер;
- `BASE_PRICE` — базовая стоимость ремонта;
- `URGENT_MULTIPLIER` — коэффициент срочности.

**Методы:**
- `device_type` (`@property`, абстрактное) — тип устройства;
- `coefficient` (`@property`, абстрактное) — коэффициент стоимости;
- `calculate_repair_cost(is_urgent)` — расчёт стоимости ремонта;
- `validate_serial(serial)` (`@staticmethod`) — проверка серийного номера;
- `from_data(data)` (`@classmethod`) — фабрика подклассов;
- `to_data()`;
- `__str__()`.

### Подклассы `Device`

Полиморфизм реализован через переопределение свойств `device_type` и `coefficient`:

| Класс | `device_type` | `coefficient` |
|---|---|---|
| `Laptop` | ноутбук | 1.3 |
| `Smartphone` | смартфон | 1.0 |
| `Tablet` | планшет | 1.1 |
| `TV` | телевизор | 1.4 |

### Класс `RequestStatus` (`Enum`)

Перечисление статусов заявки.

| Код | Значение |
|---|---|
| 1 | Принята |
| 2 | Диагностика |
| 3 | В ремонте |
| 4 | Готова к выдаче |
| 5 | Выдана |

**Методы:**
- `from_code(code)` (`@classmethod`);
- `__str__()`.

### Класс `Request`

Заявка на ремонт. Связывает объекты `Device` и `Client`, может быть связана с `Master`.

**Атрибуты:**
- `id` — идентификатор заявки;
- `device` — объект `Device`;
- `client` — объект `Client`;
- `master` — объект `Master` или `None`;
- `status` — объект `RequestStatus`;
- `is_urgent` — признак срочности;
- `created_at` — дата создания.

**Методы:**
- `cost` (`@property`) — стоимость ремонта;
- `assign_master(master)` — назначить мастера;
- `change_status(new_status)` — изменить статус;
- `from_data(...)` (`@classmethod`) — создать заявку, подтянув связанные объекты;
- `to_data()` — преобразовать в словарь;
- `__str__()`.

### Взаимодействие объектов
Client ──┐
├──► Request ──► Device
Master ──┘

- `Request` хранит ссылки на объекты `Device`, `Client` и (опционально) `Master`;
- доступ к связанным данным — через атрибуты: `request.device.model`,
  `request.client.name`, `request.master.specialization`;
- в JSON сохраняются только идентификаторы связанных объектов
  (`device_id`, `client_id`, `master_id`), при загрузке выполняется
  восстановление связей.

## Основные функции

- Регистрация заявки на ремонт устройства.
- Назначение мастера на заявку.
- Изменение статуса заявки.
- Расчёт предварительной стоимости ремонта.
- Просмотр списка заявок клиента.
- Просмотр загрузки мастера.

Функции работы с коллекциями (`add_*`, `find_*`, `filter_*`, `sort_*`,
`show_*`) сохранены как обычные функции в модулях `models/devices.py`,
`models/masters.py`, `models/requests.py`.

## Реализовано на ПР3

- Введена объектная модель: созданы классы `Person`, `Client`, `Master`,
  `Device` и его подклассы `Laptop`, `Smartphone`, `Tablet`, `TV`,
  `Request`, `RequestStatus`.
- Реализованы `__init__` и `__str__` для всех классов.
- Реализованы свойства (`@property`) и сеттеры, применена инкапсуляция.
- Использованы наследование (`Client(Person)`, `Master(Person)`,
  `Laptop(Device)` и т. д.) и полиморфизм (переопределение `device_type`
  и `coefficient`).
- Применены декораторы: `@staticmethod`, `@classmethod`, `@property`,
  собственный декоратор `@log_action` в `decorators.py`.
- Коллекции теперь содержат объекты (`list[Device]`, `list[Client]`,
  `list[Master]`, `list[Request]`) вместо словарей.
- `Request` хранит ссылки на объекты `Device`, `Client`, `Master`.
- Модуль `storage.py` преобразует JSON → объекты и объекты → JSON.
- Существующая функциональность проекта сохранена: расчёт стоимости,
  смена статуса, назначение мастера, загрузка мастера.
- Автоматизированные тесты адаптированы к объектной модели.
- Обновлён `README.md`.

## Запуск проекта

1. Клонировать репозиторий:

''Git Bash''
git clone <git@github.com:SilverYare/device-repair-tracker.git>
cd device-repair-tracker

2. Создать и активировать виртуальное окружение:

''PowerShell''
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux / macOS:
source .venv/bin/activate

3. Установить зависимости

''PowerShell''
pip install -r requirements.txt

4. Запустить программу
''Powershell''
python main.py

Пример вывода меню:

=== Сервис отслеживания ремонта устройств ===
1  Показать устройства
2  Добавить устройство
3  Показать мастеров
4  Добавить мастера
5  Добавить клиента
6  Создать заявку
7  Назначить мастера
8  Изменить статус заявки
9  Показать заявки
10 Загрузка мастера
0  Выход

5. Запуск тестов
"PowerShell"
python -m pytest

6. Проверка качества кода
"PowerShell"
.flake8
